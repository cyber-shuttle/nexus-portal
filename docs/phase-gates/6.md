## Architecture

- **§5 cross-feature isolation holds.** All four mandatory greps are zero (see below).
- **AMIE feature module is self-contained:** owns `types/schemas/api/queries/components`. Routes are thin composers. The chart wraps `shared/charts/StackedAreaUsage`; bespoke badges live inside the feature.
- **CASL gate is single-route:** `AmiePermissionGate` wraps every page so the gate logic is in one file.
- **MSW handler discipline consistent:** Zod-validate POST bodies; return `{ error, issues }` on 400; `not_found` on 404; `persistSeed()` on every mutation.
- **Shared seed contract holds:** seed/index.ts holder strategy from Phase 5 0a carry-over is unchanged; AMIE adds three new array fields (`amiePackets`, `amieEvents`, `amieReplies`) that ride the same persistence path.

## Deviations from spec / prompt

1. **`PacketAudit` endpoint not exposed.** Spec §10.1 lists Audit as a domain to surface but §10.3's endpoint inventory has no `/amie/packets/{id}/audit`. The Timeline tab synthesizes manual events from `MANUAL_*` `PacketEvent` rows, which is sufficient today. Backend-contract doc lists this as an open question — surface both feeds when the connector exposes a dedicated audit endpoint.
2. **Reverse linked-entity link** ("View originating packet" from a project / account / person) deferred to Phase 7 per prompt deliverable §1. The drawer tab notes this inline.
3. **Sub-nav is a sibling component, not a sidebar group.** Spec §10.2 + prompt §4 allowed either; the sub-nav under the page heading is more conventional for a 4-page console and keeps the sidebar uncluttered. Sidebar still has the single "AMIE Console" entry.
4. **Row click for the inbox drawer is via an explicit "View" button**, not a `<tr role="button">` row click. axe flagged nested-interactive when the row had `role="button"` plus an internal checkbox; the View button avoids it without sacrificing UX (kbd users get a real button to tab to). Documented here so the QA agent doesn't perceive it as a regression vs the spec wording.
5. **Bulk "Mark processed" calls `/resolve` with reason "Bulk mark processed".** The endpoint and audit-row spec both expect a reason; we synthesize a stock one. If product wants a richer prompt (e.g. "Mark processed — typed reason"), it's a one-line change to swap in a dialog.
6. **Sidebar persona scope.** Today the sidebar item uses `ability: { action: "manage", subject: "AmiePacket" }` which only matches admin's `manage all`. If we add a future `amie:read` role, switch the nav check to `("read", "AmiePacket")` and add the rule in `defineAbilityForRole`. Noted in the backend-contract doc.
