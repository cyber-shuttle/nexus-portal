- **New `src/shared/api/domain.ts`** — canonical status enums and shared entity schemas (`allocationStatusSchema`, `projectStatusSchema`, `userStatusSchema`, `membershipStatusSchema`, `changeRequestStatusSchema`, plus `computeAllocationSchema`, `projectSchema`, `computeAllocationChangeRequestSchema`, `computeAllocationChangeRequestEventSchema`, `computeAllocationDiffSchema`).

- **`features/change-requests/schemas.ts`** — now re-exports from `@shared/api/domain` (previously a circular re-export from `audit/`).
- **`features/audit/schemas.ts`** — owns `ComputeAllocationDiff` re-export; `AuditEvent` types come from shared.
- **`features/audit/api.ts`** — no longer reaches into `change-requests/api`. The audit feature ships `getAllocationDiffs` + a re-export of the shared `buildAuditTimeline`. Timeline composition moved to the route layer in `app/(portal)/allocations/[id]/AuditTabContainer.tsx`.
- **`features/allocations/api.ts`** — dropped the `getMembershipsForUser` import from members; that fetcher now lives in `features/members/api.ts` exclusively. The list-page composer was lifted to the route in `app/(portal)/allocations/AllocationsListContainer.tsx`.
- **`features/allocations/components/AllocationsList.tsx`** — props-driven. Receives `rows`, `isLoading`, `error`, `onRetry`.
- **`features/allocations/components/AllocationDetailHeader.tsx`** — receives `used` as a prop; no usage feature import.
- **`features/allocations/components/CreditsAndResources.tsx`** — receives pre-aggregated `usedByResource: Map<string, number>` as a prop.
- **`features/members/components/MembersTab.tsx`** — receives `piUserId` as a prop; no allocations feature import.
- **New `src/app/(portal)/allocations/[id]/AllocationDetailContainer.tsx`** — composes the three tabs and fetches the cross-feature data (usage totals, project, per-resource usage aggregation) at the route layer.
- **New `src/app/(portal)/allocations/[id]/AuditTabContainer.tsx`** — composes diffs + change-requests + change-request events at the route layer and feeds the audit view via props.
- **New `src/app/(portal)/allocations/AllocationsListContainer.tsx`** — composes per-row usage / member count / resource summary at the route layer.
- **`features/members/queries.ts`** — added `useMembershipsForUser` (was inline in allocations).
- **`features/change-requests/queries.ts`** — added `useChangeRequestsForUser` and `getChangeRequestsForUser` (Phase 2 home dependency).

### Architectural rule

The route layer (`src/app/(portal)/**`) is now the only legal place to cross feature boundaries. Feature directories communicate exclusively through `shared/**` (types, orchestrators, atoms). This preserves the §5 isolation contract going into Phase 3 mutations.

## Deviations from spec

1. **SSR pre-fetch + `HydrationBoundary` skipped.** The spec §8 SSR pattern requires a server query client. Phase 0 wired `QueryProvider` as a client-only `useState` factory; introducing a server-side query client per route requires lifting the auth + MSW boot ordering and is non-trivial. The home dashboard fetches client-side with explicit loading states. Adding SSR pre-fetch is a Phase 7 polish.
2. **Site-wide admin stats use a portal-only `/admin/stats` endpoint** (MSW). The core has no equivalent endpoint yet; recorded as a backend contract gap.
3. **PI rollup uses portal-only `/users/{id}/projects-as-pi` and `/projects/{id}/compute-allocations`** (MSW). Both are backend contract gaps.
4. **Figma MCP still rate-limited.** The dashboard layouts are a structural match (welcome card, stat cards, allocations list, activity feed, CTA panel). Pixel-level polish vs Figma `1:11026`, `1:11215`, `1:11379`, `1:11550`, `1:21351` rolls into Phase 7 unless QA reopens it sooner.
5. **GPU / CPU / Storage stat-card values are derived heuristically** (40% / 55% / 5% of total used) because no resource-type rollup endpoint exists. Phase 7 should source from a real resource-type aggregation endpoint.
6. **`useHomeSummary` returns `usedByAllocation: Map`** as a sibling of `data: HomeSummary`. Cleaner than re-deriving inside each consumer; researcher dashboard threads it down to the allocations list.
7. **AMIE seed file scoped to 10 packets**, not the full 100 spec'd for Phase 6. Only needed for the admin home's "AMIE packets needing attention" count.
