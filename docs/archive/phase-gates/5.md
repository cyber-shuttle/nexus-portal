### HIGH-1 — Credit transfer not reflected in allocation balance + audit log

After successful `POST /api/v1/tools/credit-transfer` (201 + result UI), navigating to either source or destination allocation shows pre-transfer REMAINING SUs, and the Audit log tab has no CREDIT_TRANSFER event.

Likely cause: `mocks/handlers/tools.ts` mutates a `transfers` collection but doesn't update `seed.allocations[id].initial_su_amount` / push `ComputeAllocationDiff` rows on both sides. Phase 4 contract doc says paired diff rows are required.

### HIGH-2 — New mutations don't survive sign-out / sign-in

PI submitted INCREASE_CREDITS CR (POST 201). Sign-out + sign-in as admin → request absent from `/change-requests`. Filtering by reason text confirms absence. Console shows a fresh MSW Client ID across the cycle.

Likely cause: although Phase 4 carry-over 0b put `seed` on `globalThis`, MSW worker re-init on sign-out is reading from the **module-init seed**, not the holder. The fix is to ensure both:
(a) handlers always read/write through the holder (`getSeed()` not the imported `seed`)
(b) the worker boot doesn't rebuild from `buildSeed()` if a holder snapshot exists.

Both HIGHs share root cause: **MSW handlers mutating ephemeral state instead of the persisted holder**. Phase 6 fix → re-derive seed from `globalThis.__nexusSeed` on every handler call; transfer/CR/membership handlers should mutate the holder + emit diff/event rows correctly.
