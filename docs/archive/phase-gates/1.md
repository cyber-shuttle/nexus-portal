## Deviations from spec

1. **`/users/{id}/allocations` does not exist on the core** — the spec acknowledged this in §1. `getAllocationsForUser` composes from `GET /users/{id}/compute-allocation-memberships` then fans out to `GET /compute-allocations/{id}` for every distinct allocation id. Acceptable per spec ("the backend doesn't expose `/users/{id}/allocations` directly; assemble from memberships").
2. **"Add Compute Resources" CTA uses a native `title` tooltip** rather than the shadcn Tooltip primitive. The shadcn `<Tooltip>` requires a `<TooltipProvider>` ancestor we hadn't added; the `title` attribute is functionally equivalent and accessible. Roll the proper Tooltip in Phase 2 when we also reuse it for sidebar collapse hints.
3. **Tabs rendered via a single `page.tsx` switching on `?tab=`** instead of per-tab route files. Spec explicitly allowed either pattern; chose the single-page approach to keep state in one place and let `TabsRouter` own the URL sync.
4. **Per-allocation row data on the list page (used SUs, member count, resource summary) fetches 3 extra requests per row** via `useQueries`. For 200 allocations this is bounded; the seed actually gives the researcher persona ~25 active allocations so it's small. If real users grow large lists, Phase 7 should add a server-side `summary` endpoint or a single batched query.
5. **`amber` palette added locally** (50/100/200/500/600/700). Tailwind defaults; documented in `tokens.json` with `source: default`. Same status as the Gray scale carry-over from Phase 0.
6. **Gray-scale Figma re-fetch failed** — Starter-plan rate limit still saturated. TODO line added under the gray section in `tokens.json`. Carry-over rolls into Phase 2 (or whenever the quota resets).
7. **`useAllocationUsages` query hook is wired but not rendered in any Phase 1 UI.** Spec listed it as optional ("Phase 1 just lists recent rows in the audit tab if helpful"). The audit tab focuses on diffs + change-request events as specced; usages will surface in Phase 2's home dashboard.

## Architect-review (PASS-WITH-NOTES)

Source: `comprehensive-review:architect-review` against spec §4–§9, §11, §14, §14a.

**Verdict:** PASS-WITH-NOTES. One HIGH must land before Phase 3; one MEDIUM and several LOW roll into Phase 2 / later.

### HIGH (fix before Phase 3 mutations land)

1. **Cross-feature import boundary breached in 11 places (§5 isolation rule 1).** Examples:
   - `features/audit/schemas.ts` and `features/audit/api.ts` import from `@features/allocations/schemas` and `@features/change-requests/api`.
   - `features/change-requests/schemas.ts` re-exports from `@features/audit/schemas` (circular ownership).
   - `features/allocations/api.ts` imports from `@features/members/schemas`.
   - `features/allocations/components/AllocationsList.tsx` reaches into `@features/members/api` and `@features/usage/api`.
   - `features/allocations/components/AllocationDetailHeader.tsx` reaches into `@features/usage/queries`.
   - `features/members/components/MembersTab.tsx` reaches into `@features/allocations/queries`.
   - `features/members/schemas.ts` imports from `@features/allocations/schemas`.

   Root cause: shared domain primitives (`allocationStatusSchema`, change-request schemas, status enums) ended up inside the wrong feature instead of `shared/`. Fix in Phase 2 by promoting these to `shared/api/domain.ts` (or similar) and refactoring cross-feature orchestration in components to compose at the route layer or via shared hooks.

### MEDIUM (Phase 2)

2. **`change-requests/schemas.ts` is a pure re-export from `audit/schemas.ts`** — domain ownership inverted. Move change-request schemas + types into `features/change-requests/schemas.ts` so `audit/` consumes them, then both feed from `shared/` for the truly shared status enum.
3. **Hex fallbacks in CSS-var expressions in `UsageBar.tsx:15` and `StatusBadge.tsx:29`.** Drop the fallbacks or document why they're paranoid defaults (per §14a, comment must justify the why).

### LOW (Phase 2 polish / Phase 7 a11y)

4. **Query key shape deviates in two places** (`resourceRate(resourceId)`, `project(projectId)`) from the `[feature, resource, params?]` convention. Normalize.
5. **`DataTable` row uses `role="button"` on `<tr>`.** Refactor to keep `role="row"` and nest a clickable element. Roll into Phase 7 a11y polish.
6. **Per-resource `used` SUs hardcoded to `0`** in `CreditsAndResources.tsx:87`. Wire client-side aggregation from `/usages` or get a backend endpoint in Phase 2.
