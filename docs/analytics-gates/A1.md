## ResearcherAnalytics page composition

Route shell: `src/app/(portal)/analytics/page.tsx` — server component, reads session,
delegates to `personaForAnalytics(session)`, mounts `<AnalyticsPersonaSwitch persona userId>`.

Persona switch: `src/app/(portal)/analytics/AnalyticsPersonaSwitch.tsx` — client
component, routes `'researcher' → <ResearcherAnalyticsContainer userId />`,
`'pi' → <PlaceholderPage phase={2} />`, `'admin' → <PlaceholderPage phase={3} />`.

Route-layer fan-out: `src/app/(portal)/analytics/ResearcherAnalyticsContainer.tsx`
composes:

- `useMembershipsForUser(userId)` → user's allocation IDs.
- `useQueries(getAllocation)` per allocation.
- `useQueries(getAllocationUsages)` per allocation, scoped to URL range.
- `useJobs({ user_id, from, to, limit: 25 })` and `useQueueWaitTimes({ from, to })`.
- Picks `primaryAllocation` = highest-SU active allocation; runs
  `forecast(primaryUsages, primaryAllocation, range.to.getTime())`.
- Derives KPIs via `researcherKpisFromUsage`, daily stack via
  `bucketUsageByDayResource`, donut via `resourceMix`.
- Auth gate: early-returns `<ErrorState heading="Not permitted" />` when
  `ability.can('read', subject('AnalyticsResearcher', { userId }))` is false.

Presentational surface (`src/features/analytics/components/`):

- `ResearcherAnalytics.tsx` — H1 + viewing-as pill, MetaRow toolbar
  (`LastSyncedBadge` + `DateRangePicker` + `GroupByChip` + disabled `+ Save view`
  button), 5-up KPI strip, ForecastBar card with exhaust caption, daily
  StackedAreaUsage card (clickable → DrillStack), two-up Wait time +
  Resource mix, recent jobs DataTable, single DrillStack drawer.
- `AnalyticsCard.tsx` — inline §8 card chrome (`rounded-lg border bg-card p-5`).
- `WaitTimeBars.tsx`, `ResourceMixDonut.tsx` — Recharts wrappers using
  semantic token colors.

URL state: `useUrlRange` and `useUrlGroupBy` from `src/shared/hooks`. Range
defaults to last 30 days; group-by defaults to `resource`. Every card reads
the same range — no per-card refetch.

Nav: `src/shared/layout/navConfig.ts:32-39` adds the Analytics entry at slot 2
between Overview and Allocations, gated on `read AnalyticsResearcher`. Every
authed persona sees the link (admin via `manage all`, PI/researcher via their
own subject rule).

## Open items / deferrals

- **Persona resolver gating change** — A0 shipped
  `personaForAnalytics` as "any PI membership → pi". The dev seed assigns
  `project_pi_id` from the first 8 users, which includes the researcher
  persona; that caused `loginAs('researcher')` to land on the PI placeholder
  in `/analytics`. Resolver now requires `role === 'pi'` explicitly (commit
  `94486ca`). Updated test asserts both the strict pi-role case and the
  "stale PI seed memberships do not promote a `user` role" guard. Tracks
  spec §5.4 first-bullet ("user / co_pi member-only → ResearcherAnalytics").
  Architect to confirm.
- **Detail-link coverage** — Only the Burn-vs-allocated card links to an
  existing destination. Daily / Wait time / Resource mix cards have no
  `Detail →` link in A1 because the underlying explorer surfaces don't
  exist. If the gate insists on a placeholder link to keep §8 chrome
  consistent, we can stub one in a fix-up commit.
- **MSW wait-time ignores range params** — Static seed; documented in
  `docs/backend-contracts/analytics.md`. Real backend should bucket by
  the supplied window without portal changes.
- **`jobsRun` KPI uses the truncated top-25 list** — A1 acceptable; A4
  may add a separate count endpoint or paginate.
- **`avgWait` KPI uses the same top-25 list** — same trade-off.
