## ComplianceMatrix integration

Reused from A0 (`src/shared/charts/ComplianceMatrix.tsx`). Cell function in
the container:

```ts
const matrixCell = (project, resource) => {
  if (resource.id === '__other__') { ...fold tail... }
  const input = cellInputs.get(`${project.id}::${resource.id}`);
  return complianceCell(input ?? null);
};
```

Per-(project, resource) `allocated` is a heuristic: the project's total
allocated capacity is split evenly across the resources it has usage on (we
don't have per-resource budget rows in the seed). This approximation is
called out in the container's inline comments and noted as a known
limitation for the contract doc update in A5.

## AMIE packet flow integration

`usePacketStats({ window: '30d' })` returns `{ byDay: [{ date, status, type, count }] }`. `bucketAmieByDayStatus` (private to the container) folds these into a `{ rows, seriesKeys }` shape compatible with `StackedAreaUsage`, with empty zero-padded rows for every observed date and series fixed to the four canonical statuses (NEW / DECODED / PROCESSED / FAILED).

## Open items for A4 / A5 / A6

- **Per-(project, resource) allocated SUs is approximate.** The compliance
  matrix splits a project's total allocated capacity evenly across the
  resources it has usage on. The seed exposes `resourceMappings` server-side
  but the portal doesn't enumerate them. Either expose a
  `/admin/resource-mappings` endpoint (A5 contract doc) or read the per-
  allocation per-resource budgets once the backend supports them.
- **Site-wide usage fan-out** — admin page issues N
  `/compute-allocations/{id}/usages` calls (same fan-out shape as PI). For
  100+ allocations this is slow. Spec §6.3 calls out a future
  `/compute-allocation-usages/site-total?from&to` endpoint to replace this
  loop. Update `docs/backend-contracts/analytics.md` in A5 to reference the
  admin usage pattern as another consumer of the same aggregate.
- **`Detail →` links** — no card on the admin page has a Detail → link yet;
  the AMIE `View failed →` Link is the only inline navigation. Add a
  cluster-util Detail link in A4 once `/admin/resources` ships a per-
  resource detail page that filters on the same date range.
- **Compliance matrix column fold** — overflow uses `topN` with a custom
  `makeOther` reducer to combine resource ids. The "Other resources" cell
  routes to the first allocation found in any of the folded resources;
  could be a drawer listing the contributing rows. Defer to A6.
- **At-risk table has no per-resource granularity.** The current row is
  per-allocation with `resourceId/resourceName: null`. When per-resource
  budgets land we should expand the table to (project, resource, alloc).
- **Compliance matrix `Other resources` column** — when projects don't have
  usage on any of the folded resources the cell renders empty (band:
  `empty`, value: `0`). That's the documented "no allocation" UX. We don't
  show a tooltip identifying which resources were folded; defer to A6
  polish along with the `Detail →` cards.
- **AMIE packets/day KPI uses observed-date count, not calendar-day count.**
  If the byDay stream has gap days they're not counted as zero in the
  divisor. Spec §6.3 KPI definition doesn't pin this either way; document
  in A5 if the backend lands `/amie/stats` with explicit gap-padding.
- **A2 carry-over follow-ons not addressed in A3** (still open):
  - **N2 — Multi-chip URL contract is page-local.** Slot meaning still
    differs across personas. A4 saved-views need a namespaced format.
  - **N6 — Avg burn /project label says `/mo` but value is window total.**
    A6 polish.
  - **N7 — Member-bar Y-axis renders raw user_id.** A6 polish.
