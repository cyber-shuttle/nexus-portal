## PiAnalytics composition

Route shell: `src/app/(portal)/analytics/page.tsx` — unchanged; calls
`personaForAnalytics(session)`. Persona switch
`src/app/(portal)/analytics/AnalyticsPersonaSwitch.tsx` now routes
`'pi' → <PiAnalyticsContainer userId />` (placeholder retired).

Container: `src/app/(portal)/analytics/PiAnalyticsContainer.tsx`.

- Fan-out per spec §5.2: `useProjectsAsPi(userId)` → for each project
  `useQueries(getProjectComputeAllocations)` → for each allocation
  `useQueries(getAllocationUsages)` + `useQueries(getMembershipsForAllocation)` →
  for each (allocation, user) `useQueries(getAllocationUserUsageTotal)`.
  PI's pending change-requests via `useChangeRequestsForUser(userId)` filtered
  to `change_status === 'PENDING'`.
- URL state via `useUrlRange` + `useUrlGroupBy` (3 slots: project/member/resource).
- CASL gate: `ability.can('read', subject('AnalyticsPI', { projectId }))` —
  passes if any of the PI's projects pass. Empty-projects PI falls through to
  the in-page "No projects to show" empty state, not a 403 ErrorState.
- Derived state computed at container layer:
  - Per-project rollup (`PiProjectRollup`): folds per-allocation `used`,
    `allocated`, latest end date, earliest forecast exhaust (via
    `projectForecast`), pending CR count, and the first allocation id (for
    the table row-click route to `/allocations/:id`).
  - `projectsAtRisk` via `isProjectAtRisk` (forecast < endDate − 7d) +
    `projectsAtRiskCount`.
  - `topMembers` via `topMembersAgg(contributions, 10)` — folds the tail
    beyond N into a single "Other" row.
  - `topProjects` = projects sorted by `used` desc, top 6 — feeds the
    Burn-by-project ForecastBar stack.
  - `usageByProject` re-buckets the flat usage stream with allocation id
    remapped to project id so the StackedAreaUsage stacks by project.

Presentational: `src/features/analytics/components/PiAnalytics.tsx`.

- `<h1>Analytics</h1>` + `<span>Viewing as: PI</span>`.
- Toolbar: `LastSyncedBadge` + `DateRangePicker` + `GroupByChipGroup`
  (Project + Member + Resource chips) + disabled `+ Save view` button.
- KPI strip via `<StatCardRow cols={5} data-testid="analytics-kpi-strip">`:
  Active projects · Total SU used · Avg burn /project · Projects at risk
  (negative tone when > 0) · Pending change-requests (negative when > 0).
- `Burn by project (top 6)`: vertical stack of `<ForecastBar>` per project
  with `label` set and `onClick` routing to the project's first allocation.
- `Usage trend (by project)`: `<StackedAreaUsage>` keyed by project id.
- Two-up `Member contribution` (`TopNBarChart` — see below — bar click opens
  `DrillStack` with the member's per-allocation totals) + `Resource mix`
  (`ResourceMixDonut`).
- `Projects` table at the bottom with `Project · Used / Allocated · % ·
  Forecast end · Pending CRs` columns and a row-click route to
  `/allocations/:firstAllocationId`.

New component: `src/features/analytics/components/TopNBarChart.tsx` —
Recharts horizontal `BarChart` with a `value`-typed XAxis, `label`-typed
YAxis, and `onBarClick(datum)` that yields the original `{ label, value, key }`
payload. Used by PI for Member contribution; reusable for A3 Top-projects.

New aggregations (`src/features/analytics/aggregations.ts`):

- `isProjectAtRisk(forecast, end, bufferDays=7)` — spec §6.2 KPI #4.
- `projectsAtRiskCount(rollups)`.
- `topMembers(contributions, n=10, otherLabel='Other')` — folds tail into
  one "Other" bucket so the chart stays readable.
- `projectForecast(rollups)` — earliest non-null forecast across allocations
  in a project (limiting factor).
- Type `PiProjectRollup` and `MemberContribution`.

All five new helpers are unit-tested at
`src/features/analytics/__tests__/pi-aggregations.test.ts` (12 cases).

## CASL extension

`src/shared/auth/personaScopes.ts` now exposes `myPiProjects: string[]`
alongside `myPiAllocations`. The list is the project ids where the user is
`project_pi_id`. Plumbed through `src/shared/auth/auth.ts` (Credentials
provider + JWT/session callbacks), `src/types/next-auth.d.ts` (Session/User/JWT
modules), `src/mocks/handlers/users.ts` (`/me/scopes` payload), and
`src/shared/casl/AbilityProvider.tsx` (passes `myPiProjects` into
`defineAbilityForRole`). Without this, the existing
`can('read', 'AnalyticsPI', { projectId: { $in: ctx.myPiProjects ?? [] } })`
rule was unreachable for the `pi` persona.

Test coverage: `src/shared/casl/__tests__/abilities.test.ts` gets two new
cases — PI with `myPiProjects=['proj-1']` reads `proj-1` and not
`proj-other`; researcher cannot read `AnalyticsPI` at all.

## MSW handlers

`src/mocks/handlers/jobs.ts` — both endpoints now accept `?project_id=`:

- `GET /jobs?user_id&project_id&from&to&limit` — filters jobs to the union
  of `seed.allocations.filter(a => a.project_id === project_id)` ids.
- `GET /queues/wait-time?project_id&from&to&group_by=queue` — when
  `project_id` is set, rebuilds the avg/p50/p90/sample_size payload from
  the scoped jobs (keyed on `resource_id` as a stand-in for `queue`; seed
  has no queue field — already documented in
  `docs/backend-contracts/analytics.md` as the v1 limitation).

Researcher MSW handler is untouched — still returns the pre-baked
`seed.queueWaitTimes` when no `project_id` filter is set.

## Open items for A3 / A6

- **Per-allocation/per-user totals fan-out** — PI with many memberships
  across many projects fires O(allocations × members) queries. Spec §6.2 +
  §12 acknowledge this for v1; backend ticket for an aggregate endpoint
  remains tracked in `docs/backend-contracts/analytics.md`. Update the
  contract doc in A5 to reference the PI usage pattern.
- **Detail links** — `Burn by project` rows already deep-link to the first
  allocation. `Usage trend`, `Member contribution`, `Resource mix` cards
  have no `Detail →` link yet; same trade-off as A1 — defer until the
  explorer surfaces exist.
- **TopNBarChart `onClick` for "Other" row** — currently swallowed
  (no drill destination). When A3 widens the drill cascade we can expand
  "Other" inline instead of opening a drawer.
- **Member contribution labels** — bar Y-axis renders the raw `user_id`
  (email). A future polish pass can resolve to first+last name via
  `useUser` — kept out of scope here because the PI container is already
  N+1-heavy and the bars route to a drawer titled by the same id.
- **Average burn KPI** — `totalSuUsed / numProjects` per spec §6.2 row 3
  ("Avg burn /project"). The unit reads `<value>/mo` for spec parity, but
  numerator is window total (not monthlyized). Document or adjust in A6.
- **`projectsAtRisk` deltaTone** — A2 sets `negative` when count > 0.
  No prior-period delta value is shown because we don't have a "previous
  window" snapshot yet (saved-views land in A4).
- **Multi-chip URL contract** — slot order (project=0, member=1, resource=2)
  is implicit. A4 saved-views must round-trip the slot list verbatim;
  documented in `useUrlGroupBy` JSDoc and in this report.
