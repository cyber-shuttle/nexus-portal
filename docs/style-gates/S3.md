## Primitives & wiring

### TabsRouter (§7.4 + new right-slot affordance)

`src/shared/ui/TabsRouter.tsx` gained a `rightSlot` prop that accepts either a single `ReactNode` (sticky across tabs) or a `Record<tabValue, ReactNode | undefined>` (per-tab). The tab strip + right slot share the same `border-b border-border`, so the new chrome is visually flush.

Discrimination between the two shapes uses a small `isReactElement` predicate: React elements are objects with `$$typeof`; plain records are not. Tests at `src/shared/ui/__tests__/TabsRouter.test.tsx` cover both shapes plus the "no slot" case.

### AllocationDetailHeader (§8, `src/features/allocations/components/AllocationDetailHeader.tsx`)

Old shape: data-fetching, container-style component returning a `rounded-lg border bg-card p-6` card.

New shape: pure presentational component. Container does the data wiring (allocation + project + PI user + members + resources + usage), passes props (`allocation`, `piName`, `memberCount`, `resources`, `remainingCredits`, `updatedAt`) — header just lays things out.

Status pill routes through the new `MetaItem variant="status"`:
- `ACTIVE` + within end-date window → `success` ("Active", green dot)
- `ACTIVE` + past end-date → `warning` ("Expired")
- anything else → `danger` ("Inactive")

The 3-up StatCardRow always renders the credits card and slices `resources.slice(0, 2)` for the two progress cards — extra resources are visible in the Credits & Resources tab.

`buildHeaderResources()` exported helper joins the resource list with the per-resource `usedByResource` map; the container calls it so the join logic is unit-tested in isolation.

### Container wiring (`src/app/(portal)/allocations/[id]/AllocationDetailContainer.tsx`)

- New deps: `useUser` (for PI name), `useAllocationMembers` (for member count + AddMemberDrawer's exclusion list), early-return `CardSkeleton` / `ErrorState` while the allocation loads.
- `defaultValue` flipped to `"users"`.
- `rightSlot` is the per-tab record:
  - `users` → `<Button variant="default">Add user</Button>` (gated by `canManageMembers`)
  - `credits` → `<Button variant="outline">Request extension</Button>`
  - `audit` → `undefined`
- AddMemberDrawer mount moved from MembersTab to the container so it lives next to the Add-user trigger.
- `RequestExtensionDrawer` stays in the container (was already there).

### MembersTab cleanup (`src/features/members/components/MembersTab.tsx`)

- Dropped `AddMemberDrawer` import, `addOpen` state, the top filter row's "Add member" button, the in-tab AddMemberDrawer mount, and the `allocationEndTime` prop (the container's AddMemberDrawer needs `allocationEndTime`, MembersTab doesn't anymore).
- The "N members · Roles: PI, Co-PI, …" legend strip stays; the right-aligned button slot is gone.

### CreditsAndResources cleanup (`src/features/allocations/components/CreditsAndResources.tsx`)

- Dropped the `Button` import, the `onRequestExtension` prop, and the inline header row's "Request extension" button. Section header is now just title + subtitle, no trailing button.

### format.ts helpers (`src/lib/format.ts`)

- `formatNumber(n)` — thousand-separated decimal (alias of `formatSU` for non-SU callsites — kept both so credit/user counts read with the right verb).
- `formatRelative(input, now)` — coarse "x min/hr/day ago" formatter for the credits card's "Updated …" sub-line; falls back to `formatDate` for >30 days.

## Open items / deferrals

1. **SU → hours conversion** — Spec §8 labels the per-resource card value as `"<used>/<total> hrs"`. We don't have a wire-level rate per resource on the bare resource model (`getResourceRatesEffective` is a separate fetch per resource), so the card currently displays the raw SU number with the "hrs" label (rate of 1). A follow-up could fan out `useResourceRatesEffective` calls inside the container and divide, but the visual is already correct against the Figma reference (which shows `6/6 hrs` style). Flag for Lahiru: do we want the rate-aware conversion now, or is the SU display fine?
2. **AddMemberDrawer's primary button label** — Still says "Add member" inside the dialog, while the trigger now says "Add user". The drawer's verb wasn't called out for renaming in the spec; leaving as-is to keep e2e selectors stable. Trivial change if QA wants alignment.
3. **PlaceholderPage + other pre-existing forbidden patterns** — still deferred to S4 sweep per spec.
4. **StatCard `trend` prop** — still flagged for S5 removal.
5. **Three resources on small viewports** — the 3-up `StatCardRow` already collapses to 1-col below `md`; no extra handling needed for the "more than 2 resources" case beyond the existing slice-to-2 cap.
